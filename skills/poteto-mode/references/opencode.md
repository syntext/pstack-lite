# OpenCode runtime conventions

These conventions translate platform mechanics; the workflow's task and evidence requirements still apply.

Paths to bundled scripts and references are relative to the skill's base directory inside the loaded plugin package, not the target project's working directory. Run project commands with the target directory as `workdir`; for example, invoke the watcher's absolute script path while working in the target repository.

- **Delegation and models:** read `../../setup-pstack/references/model-configuration.md`. Use `poteto-agent` for implementation, `general` for investigation needing shell/MCP tools, and `explore` for read-only code exploration and review. `comment-sicko` is the comment reviewer. A child must receive its scope, model, output paths, and verification requirements explicitly. General-purpose investigation briefs remain report-only even when their tools permit writes; use only read actions on external systems.
- **Task lists:** use the client's task-list tool when available; otherwise keep a Markdown checklist in the conversation or task artifact. Preserve the playbook's steps and skip reasons.
- **Skill authoring:** follow `../playbooks/authoring-a-skill.md`. OpenCode loads `SKILL.md` directly; no companion authoring plugin is required.
- **Diff cleanup:** before commit, remove narrating comments, unsupported guards, dead compatibility paths, and unrelated edits. Use `no-comments` and the relevant principles. This replaces the unbundled `deslop` dependency.
- **Live verification:** use the installed browser, terminal, simulator, or project harness appropriate to the surface. Discover the actual available tools rather than assuming `control-ui` or `control-cli`. If the surface cannot be driven, report the missing capability and unverified checks.
- **Session history:** from the target project, use `opencode session list --format json` and `opencode session export <session-id>` for known relevant sessions. Prefer a client-provided read-only session tool if available. Export only sessions in scope; do not scan another project's history. Store an export in a task-local temporary directory if a child needs a file. Use the current session ID from the environment, or ask for the session reference. A supplied transcript or labeled conversation digest is a fallback, not proof of tool execution. For children, pass known session IDs instead of guessing filesystem paths.
- **MCP discovery:** inspect the current tool catalog and available MCP resources; `opencode mcp list` can identify configured servers. Use only available read operations for investigation. Report missing sources as gaps.
- **PR watching:** run the existing watcher directly, using `--status-only` for a one-time check. A requested background watch can use a background shell/subagent and its completion notification; after a push, start the next watcher only when the previous one has finished. No persistent wake scheduler is bundled.
- **Mode persistence:** after explicit activation, keep applying poteto-mode to matching follow-ups until the user opts out. This is a conversation instruction, not a Cursor mode/reminder hook. After lost context or a fresh session, load the skill again.
